# SnowBrawl — сервер мультиплеера

Браузерная игра в снежки 1×1…4×4: PvP команда на команду и кооперативный PvE против волн.
Этот репозиторий содержит сервер на Go, который отдаёт клиент игры, держит WebSocket-соединения,
сводит игроков в матчи (комнаты со списком и кодом, пустые слоты занимают боты) и исполняет
общую симуляцию `web/sim/sim.js`.

Игроки заходят на один адрес, вводят ник и играют. Регистрации нет, базы данных нет.
Боевой сервер: **https://snowbrawl.ru**

## Быстрый старт

```bash
make dev          # go run с клиентом с диска, http://localhost:8080, админка token=dev
make test         # тесты (юниты + интеграционные с WebSocket-клиентами)
make bench        # нагрузка goja: 17 матчей 4×4 при 20 тиках/с
make build        # bin/snowbrawl-server с версией из git
```

Продакшен: см. [docs/RUNBOOK.md](docs/RUNBOOK.md) (один Docker-образ, `docker compose up -d`).

## Устройство

| Каталог | Что там | Владелец |
|---|---|---|
| `cmd/snowbrawl-server` | точка входа | сервер |
| `internal/` | hub, комнаты, список комнат, матчи, WebSocket, goja-раннер, админка | сервер |
| `web/sim/sim.js` | общая симуляция: физика, попадания, способности, ИИ ботов | **разработчик игры** |
| `web/client/`, `web/index.html` | экраны, рендер, звук, сетевой и оффлайн-драйверы, ввод (`intent.js` — слой намерений, `touch.js` — стики, `device.js`/`settings.js`), PWA-манифест | **разработчик игры** (эталон сделан сервером) |
| `deploy/` | Dockerfile, docker-compose, Caddy, скрипт выкладки | сервер |
| `docs/` | архитектура, протокол, контракт sim.js, версии, эксплуатация, передача | все |

Игрок из главного меню выбирает раздел: **Режим PVP**, **Режим PVE**, **Обучение** или
**Настройки**. PVP и PVE ведут сразу в список комнат своего раздела: открытые и закрытые комнаты
с пагинацией по 25 и статусом «Ожидание» или «Матч», а над списком одной строкой — четыре клетки
для кода друга (как только введены четыре цифры, вход происходит сам) и кнопка «Создать комнату».
Разделы не пересекаются: код PVE-комнаты в разделе PVP не сработает. В комнате хост задаёт размер,
арену, сложность ботов и доступ, все отмечаются кнопкой «Готов» (когда готовы все, матч начинается
сам), а бойца каждый выбирает себе сам. Слот в комнате — это боец матча: войти можно и в комнату с
идущим боем, тогда лобби показывает состав, HP и таймер, а кнопка «Присоединиться к матчу» сажает
игрока за бойца его слота. Выход из боя оставляет в лобби, место держится за игроком.

«Обучение» — список из семи сценариев: «Основы» (семь шагов: ходьба, замах, перезарядка, укрытия,
способность; класс бойца выбирает игрок) и по одному обучению на каждого героя из трёх шагов про
его способность и тактику. Пройденные отмечаются, порядок свободный. Соперник появляется, когда до
него доходит очередь, и добить ученика не может.

В главном меню есть общий чат: мат маскируется, своё сообщение можно удалить, а «Админ» и
«Создатель» (роли выдаются по IP через админку и красят ник) удаляют и чужие.

Клиент один для ПК и телефона. На ПК управление одно: WASD — движение, удержание ЛКМ — замах и
бросок (E — отмена замаха), Q или ПКМ — способность. На сенсорном экране (определяется по `pointer: coarse`, переключается
в настройках) включаются два плавающих стика: левая половина экрана — движение, правая — замах,
прицел и бросок (вернуть палец в центр — отмена), кнопка способности справа (для Щита — мини-стик
направления). Обе ориентации; в ландшафте арена
вписана по высоте, HUD на боковых полях. Мышь и стики выдают одни и те же команды протокола, поэтому
ПК и телефоны играют в общих комнатах без правок сервера.
