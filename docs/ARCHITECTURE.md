# Архитектура

## Главное решение: сервер-авторитарный, симуляция общая на JS

Правила игры (физика снежков, попадания, способности, ИИ ботов) живут в одном файле
`web/sim/sim.js`. Его исполняют двое:

- **браузер** — в оффлайн-режиме «тренировка с ботами» (и как справочник констант: арены, роли);
- **сервер** — внутри Go через встроенный JS-движок [goja](https://github.com/dop251/goja),
  по одной изолированной `goja.Runtime` на матч.

Сервер — единственный источник истины в сетевом матче: клиенты присылают ввод
(`move`, `chargeStart`, `aim`, `throw`, `special`), сервер 20 раз в секунду делает шаг
симуляции и рассылает полный снапшот состояния. Клиент только рисует, интерполируя между
двумя последними снапшотами с задержкой ~100 мс, без предсказания.

Почему так, а не иначе:

- Порт правил на Go означал бы две реализации одной игры и двойную работу при каждом
  обновлении. Здесь обновление игры = замена одного файла.
- Lockstep потребовал бы детерминизма во всех браузерах и не даёт ботов «бесплатно».
- Хост-авторитарная схема умирает вместе с хостом и даёт хосту читерить.

Цена: goja медленнее V8 примерно в 20–50 раз. Бенчмарк `BenchmarkFullLoad`
(17 матчей 4×4 при 20 тиках/с — целевая нагрузка на 100 игроков) занимает ~15 % одного
ядра на Apple M-серии. Порог для отката на порт в Go был 30 %.

## Пакеты

```
cmd/snowbrawl-server   main: конфиг, логгер, gin-роутер, graceful shutdown
internal/config        флаги + переменные окружения SNOWBRAWL_*
internal/protocol      типы сообщений, версия протокола, валидация ника и кода комнаты
internal/ws            WebSocket-соединение: лимит частоты, очередь отправки, учёт соединений
internal/session       Player: токен, ник, где находится (menu/queue/room/match)
internal/room          комната с кодом из 4 цифр и лобби (чистые данные)
internal/matchmaking   очереди Quick Match по режимам (чистые данные)
internal/sim           goja-раннер: Compile(sim.js) → Program, Program.NewMatch → Match
internal/match         цикл матча: тик, ввод → sim, снапшоты → игрокам, AFK/дисконнект → бот
internal/hub           всё вместе под одним мьютексом + фоновые таймауты + дренаж + Stats
internal/admin         /healthz, /api/version, /api/online (счётчик онлайна для меню), /admin/* (token)
internal/web           отдача клиента: embed или --web-dir, подстановка __BUILD__ в index.html
web.go                 go:embed web  (корень модуля, потому что embed не ходит наверх)
```

## Потоки и блокировки

- `hub.Hub` — один мьютекс на все комнаты, очереди, сессии. Все обработчики сообщений
  короткие, поэтому одного мьютекса достаточно и он исключает гонки между комнатами.
- `match.Match` — своя горутина с тикером и свой мьютекс. Публичные методы (`Input`,
  `Attach`, `Detach`, `Leave`, `Stop`) берут только мьютекс матча, наружу из-под него ничего
  не вызывают. Поэтому hub может звать их под своим мьютексом без риска дедлока.
  Колбэк `onEnd` матч вызывает уже без мьютекса, а hub в нём берёт свой.
- `ws.Conn.Send` неблокирующий: очередь 256 сообщений, при переполнении соединение
  закрывается («slow consumer»), чтобы один зависший клиент не тормозил тик.
- goja не потокобезопасен: к `sim.Match` обращаются только под мьютексом матча.

## Жизненный цикл игрока

```
hello ─► welcome(resume) ─► menu
  menu ─► queue.join ─► queue.status… ─► match.start ─► snapshot… ─► match.end ─► menu
  menu ─► room.create/join ─► room.state… ─► (host) room.start ─► match … ─► room.state (лобби)
```

- Сессия = токен в localStorage. По нему игрок возвращается после F5 или обрыва
  в ту же очередь/комнату/матч (`welcome.resume`).
- Обрыв связи в матче: бойца сразу ведёт бот, место держится `ReconnectTTL` (60 с).
  Сознательный выход (`match.leave`) — бот до конца матча.
- Нет ввода `AFKTimeout` (20 с) при живом соединении — бот; любой ввод возвращает управление.
- Если в матче не осталось людей (все ушли или истёк TTL) — матч уничтожается.
- Матч заканчивается KO всей команды, ничьёй по таймеру (5 мин, правило в sim.js),
  `abandoned` или `shutdown`.

## Границы и лимиты

- 200 WebSocket-соединений (503 сверх), 30 сообщений/с на соединение (закрытие сверх),
  3 живые комнаты на IP, сообщение ≤ 4 КБ, пустая комната живёт 10 мин.
- Ник 2–16 символов (буквы, цифры, пробел, дефис, подчёркивание), дубли в матче — суффикс « (2)».
- Сила броска считается клиентом и присылается в `throw`, сервер зажимает в [0,1] и сверяет
  со своим таймингом с допуском 0.25: читерство на силе броска в игре для друзей не стоит защиты.

## Обновления без параллельных версий

Клиент вшит в бинарник и получает версию сборки через `<meta name="build">`. В `hello`
он присылает её; при расхождении сервер отвечает `reload`, и страница перезагружается.
Выкладка идёт через дренаж (`POST /admin/drain`): новые матчи не стартуют, всем показан
баннер, скрипт `deploy/deploy.sh` ждёт окончания матчей до 3 минут и перезапускает контейнер.
