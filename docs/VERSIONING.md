# Версионирование и релизы

Три независимые версии:

| Что | Где задаётся | Кто видит | Когда менять |
|---|---|---|---|
| **Сборка** (`build`) | git-тег `vX.Y.Z`, вшивается в бинарник `-X main.buildVersion` | подвал меню, `/api/version`, `/healthz`, логи, `hello`/`welcome` | каждый релиз, автоматически |
| **Симуляция** (`sim`) | `SIM_VERSION` в `web/sim/sim.js` | подвал меню, админка, логи старта | при изменении правил игры |
| **Протокол** (`proto`) | `internal/protocol.Version` и `SBNet.PROTO` в `web/client/net.js` | `hello`/`welcome`, `/api/version` | только при несовместимом изменении сообщений |

Клиент вшит в бинарник, поэтому клиент и сервер всегда одной сборки. Старая вкладка после
деплоя присылает в `hello` старый `build` и получает `reload`.

## Релиз

```bash
git tag v0.2.0 -m "Что нового"
git push origin v0.2.0
```

GitHub Actions (`.github/workflows/release.yml`): тесты → образ `ghcr.io/<owner>/snowbrawl:v0.2.0`
и `:latest` → GitHub Release с автозаметками → (если заданы секреты) выкладка на VPS через
`deploy/deploy.sh` с дренажом.

Semver для тегов:

- **patch** (`v0.2.1`) — исправления без изменения правил игры и протокола;
- **minor** (`v0.3.0`) — новые возможности, новые правила в sim.js, совместимые изменения протокола;
- **major** (`v1.0.0`) — несовместимый протокол (`proto` +1) или смена схемы поставки.

## Откат

Откат = деплой предыдущего тега: на VPS `./deploy.sh v0.1.9`. Состояния на диске нет,
поэтому откат всегда безопасен. Старые образы остаются в GHCR.

## CHANGELOG

`CHANGELOG.md` ведём вручную по [Keep a Changelog](https://keepachangelog.com/ru/): при
каждом релизе раздел «Unreleased» становится разделом версии.
