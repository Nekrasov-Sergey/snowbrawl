# Эксплуатация (RUNBOOK)

Всё, что нужно, чтобы поднять, обновить и починить сервер, не читая код.

## Что нужно

- VPS: Ubuntu 24.04, 1–2 vCPU, 2 ГБ RAM, 20 ГБ диска, публичный IPv4. На 100 игроков онлайн
  хватает с большим запасом (сервер занимает ~50–100 МБ RAM и доли ядра).
- Docker и Docker Compose plugin.
- Открытые порты: 80, 22 для SSH; при TLS ещё 443 по TCP и по UDP (HTTP/3 в Caddy).

## Первый запуск на VPS

```bash
# 1. Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker

# 2. Каталог и файлы
sudo mkdir -p /opt/snowbrawl && sudo chown $USER /opt/snowbrawl && cd /opt/snowbrawl
# скопируйте сюда deploy/docker-compose.yml, deploy/docker-compose.tls.yml,
# deploy/Caddyfile, deploy/deploy.sh, deploy/.env.example  (scp или git clone репозитория)
cp .env.example .env
nano .env            # SNOWBRAWL_ADMIN_TOKEN=$(openssl rand -hex 24), образ, домен

# 3. Запуск (без домена, по IP)
docker compose up -d
curl http://127.0.0.1/healthz
```

Игра: `http://<IP-сервера>/`. Админка: `http://<IP>/admin/?token=<SNOWBRAWL_ADMIN_TOKEN>`.

### Включить домен и HTTPS

Боевой адрес игры — `https://snowbrawl.ru`, домен у регистратора Timeweb.

1. Создать A-записи на IP сервера для домена и для `www`. Если домен куплен в той же панели, где
   стоит VPS, Timeweb делает это сам — проверьте: `dig +short A snowbrawl.ru @8.8.8.8` должен
   вернуть IP сервера. Пока публичные резолверы домен не видят, дальше идти нельзя: Let's Encrypt
   не выпустит сертификат, а на неудачи есть лимит (5 в час на домен).
2. Открыть порт 443 по TCP и UDP (`sudo ufw status` либо `sudo iptables -S`, плюс фаервол в панели
   хостера).
3. В `.env` указать `SNOWBRAWL_DOMAIN=snowbrawl.ru` и `SNOWBRAWL_TLS=true`.
4. Перезапустить со стеком TLS:

```bash
docker compose -f docker-compose.yml -f docker-compose.tls.yml --profile tls up -d
docker compose logs -f caddy     # дождаться строки о выпущенном сертификате
```

Caddy сам получит и будет продлевать сертификат Let's Encrypt. Заход по IP и по `www` редиректится
на канонический адрес.

В этом режиме сервер публикует порт только на loopback (`127.0.0.1:8080`), наружу смотрит один
Caddy. Локальные проверки поэтому идут туда же: `curl http://127.0.0.1:8080/healthz`. Стучаться в
`http://127.0.0.1/` бесполезно — у Caddy нет сайта для такого `Host`, он ответит 404.

Почта аккаунта ACME задана в `Caddyfile` — на неё Let's Encrypt напишет, если продление сертификата
однажды сломается. Сертификат живёт 90 дней и продлевается автоматически за 30 дней до конца.

HTTP/3 работает по UDP, и ядру нужен буфер побольше стандартного. Проверить и поднять:

```bash
sysctl net.core.rmem_max     # мало, если 212992
printf 'net.core.rmem_max=7500000\nnet.core.wmem_max=7500000\n' | sudo tee /etc/sysctl.d/99-snowbrawl-quic.conf
sudo sysctl --system && docker compose -f docker-compose.yml -f docker-compose.tls.yml --profile tls restart caddy
```

Признак, что буфер мал, — строка `failed to sufficiently increase receive buffer size` в логах Caddy.

## Обновление

Автоматически: пуш тега `v*` в GitHub → образ → выкладка (см. VERSIONING.md). Версия сборки в
образе — `<тег>+<короткий SHA>` (например `v0.2.0-rc.5+74d573f`): она попадает в `?v=` статики,
так что даже повторный деплой того же тега обновляет кэш браузеров.
Вручную на VPS:

```bash
cd /opt/snowbrawl && ./deploy.sh v0.2.0     # или ./deploy.sh для latest
```

Скрипт включает дренаж (игроки видят баннер, новые матчи не стартуют), ждёт окончания
текущих матчей до 3 минут, обновляет контейнер, проверяет `/healthz`.

Откат: `./deploy.sh v0.1.9`.

## Диагностика

| Симптом | Что делать |
|---|---|
| Сайт не открывается | `docker compose ps`, `docker compose logs --tail 200 server`; `curl -v http://127.0.0.1:8080/healthz` |
| Открывается, но «нет соединения с сервером» (красная точка слева сверху) | WebSocket не проходит: проверьте, что за прокси (если он свой) включён апгрейд `Upgrade: websocket`; Caddy делает это сам |
| Игроки жалуются на «сервер переполнен» | лимит `SNOWBRAWL_MAX_CONNS` (200) — поднять в `.env` и `docker compose up -d` |
| Матчи «залипли» | `/admin/state` покажет матчи и тики; матч без людей удаляется сам через 60 с, любой матч заканчивается таймером через 5 мин |
| Нужно срочно перезапустить | `docker compose restart server` — текущие матчи получат «матч прерван», клиенты переподключатся сами |
| Посмотреть кто онлайн | `/admin/?token=…` или `curl -H "X-Admin-Token: …" http://127.0.0.1:8080/admin/state` |
| Дренаж завис после неудачной выкладки | `curl -X DELETE -H "X-Admin-Token: …" http://127.0.0.1:8080/admin/drain` |

Адреса в таблице — для режима TLS, где 80-й порт занят Caddy, а сервер слушает `127.0.0.1:8080`.
Без TLS сервер сам на 80-м: `http://127.0.0.1`.

### Что показывает админка

`/admin/?token=…` — одна страница. Состояние приходит потоком (`/admin/stream`, SSE): сервер
отправляет сводку сразу, как она изменилась, поэтому опроса и надписи «обновлено N с назад»
больше нет. Кнопка «Пауза» разрывает поток, повторное нажатие подключает заново.

Кроме токена в админку пускает роль **«Создатель»**: у такого игрока в главном меню игры есть
кнопка «Админка», и она открывает `/admin/` вообще без токена — сервер сверяет адрес запроса со
списком ролей. Токен клиенту при этом не выдаётся. Условие, при котором это безопасно: за прокси
обязателен `SNOWBRAWL_TRUST_PROXY=true` **и** порт сервера должен смотреть только в loopback (так
и сделано в профиле tls). Иначе адрес подделывается заголовком `X-Forwarded-For`, и админка
открывается любому. Роль «Админ» доступа к панели не даёт — только права в чате.

- **Игроки** — все сессии: ник (цветом роли), роль, где сейчас, на связи ли, когда зашёл и сколько
  в игре, IP и кнопки управления. Список отсортирован по времени входа, старые сверху. Отключённые
  приглушены: сессия живёт ещё 60 секунд после обрыва, игрок за это время может вернуться.
  Обучение идёт целиком в браузере, поэтому сервер знает о нём только со слов клиента:
  строка «тренировка с ботами 1×1, Раннер, арена 0» — это отметка, а не матч на сервере,
  и в разделе «Матчи» такой игры не будет.
- **Матчи** — состав по командам с никами, время начала и длительность боя (до конца отсчёта в
  колонке «длительность» стоит «отсчёт»). `🤖` — бот из добора, `⚠ бот` — за человека временно
  играет бот (обрыв связи или бездействие), `⚠ вышел` — ушёл насовсем.
- **Комнаты** — код, участники (хост помечен `★`, готовый `✓`), игра, размер, арена и доступ
  (открытая или `🔒 закрытая`).
- **Роли по IP** — кому выданы «Админ» и «Создатель», и кнопка «Снять». Выдать роль можно из
  строки игрока (выпадающий список) или вручную по адресу в форме под таблицей. Роль меняет цвет
  ника (создатель — золотой, админ — фиолетовый) и даёт права в чате: админ удаляет сообщения
  обычных игроков, создатель — любые, автор всегда может удалить своё.
- **Баны по IP** — заблокированные адреса и «Разбанить». Бан закрывает игроку соединение и
  выкидывает его из комнаты и матча, новые подключения с адреса отклоняются; сама страница игры
  при этом открывается. Забанить адрес с ролью «Создатель» нельзя — сначала снимите роль.
- **Чат** — сколько сообщений в буфере и кнопка «Очистить чат»: стирает историю у всех сразу.

**Роли и баны — по адресу, а не по игроку.** За одним IP может сидеть несколько человек (NAT,
мобильный оператор): перед баном страница показывает, кого именно затронет. Кроме того, роли
имеют смысл только если сервер видит настоящий IP: за Caddy нужен `SNOWBRAWL_TRUST_PROXY=true`,
а порт сервера при этом обязан смотреть только в loopback (так и сделано в профиле tls) —
иначе адрес подделывается заголовком `X-Forwarded-For`, и «Создатель» достаётся кому угодно.

Кнопок управления дренажом на странице нет: его включает и снимает только `deploy.sh` при выкладке.
Если выкладка оборвалась и баннер «Идёт выкладка новой версии» не ушёл — снимите вручную командой
из таблицы диагностики.

Логи — JSON в stdout контейнера, ротация 5×20 МБ настроена в compose:
`docker compose logs -f server`. Уровень: `SNOWBRAWL_LOG_LEVEL=debug` в `.env`.

## Переменные окружения сервера

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SNOWBRAWL_ADDR` | `:8080` | адрес прослушивания внутри контейнера |
| `SNOWBRAWL_ADMIN_TOKEN` | — | токен админки; пустой = админка выключена |
| `SNOWBRAWL_WEB_DIR` | — | каталог клиента с диска (разработка) |
| `SNOWBRAWL_MAX_CONNS` | 200 | максимум WebSocket-соединений |
| `SNOWBRAWL_LOG_LEVEL` | info | debug/info/warn/error |
| `SNOWBRAWL_LOG_PRETTY` | false | человекочитаемые логи |
| `SNOWBRAWL_TRUST_PROXY` | false | брать IP из X-Forwarded-For (за Caddy — true) |
| `SNOWBRAWL_RECONNECT_TTL` | 60s | сколько держать место за отключившимся |
| `SNOWBRAWL_AFK_TIMEOUT` | 20s | бездействие до передачи бойца боту |
| `SNOWBRAWL_COUNTDOWN` | 3s | отсчёт перед началом матча (0 — сразу в бой) |
| `SNOWBRAWL_ROOM_TTL` | 10m | жизнь пустой комнаты |
| `SNOWBRAWL_MODERATION_FILE` | `/data/moderation.json` в compose | файл с ролями и банами по IP; пустой — только в памяти |
| `SNOWBRAWL_ROOMS_PER_IP` | 3 | живых комнат на IP |
| `SNOWBRAWL_MSG_RATE` | 30 | сообщений/с на соединение |
| `SNOWBRAWL_DRAIN_TIMEOUT` | 3m | сколько показывать «до перезапуска» |

## Резервные копии

Почти не нужны: сервер хранит на диске только роли и баны по IP —
`/data/moderation.json` в томе `snowbrawl_data`. Всё остальное (комнаты, матчи, чат) живёт в
памяти. Сохранить стоит `.env` (токен админки, домен) и при желании сам файл:

```bash
cd /opt/snowbrawl
docker compose cp server:/data/moderation.json ./moderation.json.bak
```

`docker compose down -v` удаляет том вместе с ролями и банами — при обычной выкладке
(`deploy.sh`, `up -d`) том сохраняется.

Если файл окажется повреждённым, сервер всё равно поднимется: испорченный файл будет отложен
рядом с суффиксом `.bad`, роли и баны сбросятся, в логах появится ERROR, а в админке — красная
строка об этом. Уронить игру из-за битого файла было бы хуже, но потеря обязана быть заметной.

## Безопасность

- Персональные данные не собираются: только ник, выбранный игроком, и IP в логах
  (стандартные технические логи).
- Админка защищена токеном; при утечке — сменить в `.env` и `docker compose up -d`.
- `/data/moderation.json` содержит IP-адреса и ники, права на файл 0600. Это единственное место,
  где сервер хранит что-то дольше своего запуска.
- Обновления ОС: `sudo apt update && sudo apt upgrade` раз в месяц; Docker-образ
  распространяется через GHCR из этого репозитория.
